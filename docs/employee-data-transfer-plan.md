## 1. 最新目标与范围变更

用户要的是“把旧站业务资料整体搬到新站，除不需要详细历史订单外，使用内容尽量与旧站一致”，不是只搬选中的员工。此前“共享配置不迁移、二级管理员只做对应、新站重新配置方案”的限制已被本次要求替代。

后台新增仅 super_admin 可用的「資料遷移」，包含「導出」「導入」「紀錄」。标准流程默认「全站導出」，不要求逐个选择员工或管理员，也不要求先手工建立二级管理员、分组及业务配置。小范围选择只作为内部演练、覆盖前安全备份和故障补传能力，不是正常迁移的必选步骤。

已确认超管规则：保留新站超级管理员账号、密码和登录身份；旧站超级管理员账号及其密码校验资料不覆盖新站超管，旧站超管名下业务资料对应给新站超管。二级管理员账号、密码校验资料、角色、启停状态和关联业务一并迁移，继续管理原来的员工。其他非超管特殊角色在清单中列明并保留原权限，不擅自升级权限。

“业务一致”要通过管理员、员工、设置、内容、财务、统计和自动化续接的验收证明，不等于逐字节复制数据库，也不复制旧项目的域名、访问密钥、会话和运行中的事务。

## 2. 已确认的业务决定

1. 默认全站全部导出，不逐个选员工；后台业务设置和非超管管理员纳入迁移，不再让用户逐项重建。
2. 保留新站超管；二级管理员与员工用原用户名和密码重新登录。迁移密码校验资料，不迁移明文密码和登录会话。
3. 旧站超管的员工、非超管管理员层级、设置、角色、任务等纳入迁移的业务归属，改写为新站超管；其他管理员和员工关联按实际 ID 对应重写。公告已排除，不改写新站现有公告归属。
4. 钱包、冻结金额、总收入、账本、账户变动、提款全状态一起迁移；待处理提款保持待处理，切站后只在新站继续处理同一笔提款。
5. 已完成历史订单只带 ID、员工归属、状态、佣金、佣金率、创建/处理时间，支撑每日明细和累计数；不带真实订单金额、订单号、交易号、产品与交易内容。用户已确认继续营业所需派单池、交单校验原文及防重复使用状态保留，不属于被省略的已处理订单详情。处理中订单不导入，只报告；当前累计订单函数也数 processing，要求无差异的正式切站必须先处理至零，不能带着未完成订单却声称累计数完全一致。
6. 同用户名员工以本次导入资料为准，包含标签、备注等完整业务属性；“新的”指本次导入包，不是按记录更新时间自动选两站中较新的字段。独立备份并校验 → 现有封存留证流程 → 再干跑 → 导入，不相加钱包，不把目标旧字段留作默认值。
7. 相同聊天角色仍合并历史，已有角色属性保持新站值；歧义、多旧合一、可见范围调整必须确认。目标已有不同设置时不能同时宣称设置与旧站完全一致。
8. 网页内加密导出、新站输原口令自动解密；正常迁移不需要安装解密软件，独立工具只作应急。
9. 导出和导入均有真实进度、暂停、故障报告及可验证续传；未核对完整不能标成功，维护窗口结束前不放行业务。
10. 员工标签、备注、置顶、状态、归属及全部业务属性完整迁移；除已明确排除项和已确认的超管身份映射外，以后台员工列表/详情显示及筛选结果逐项一致为验收目标，不只核对账号存在或总数量。
11. 旧站登录历史保留为该导入员工的历史记录，迁移后在新站产生的新登录记录继续追加到同一员工的列表和统计，按实际时间连续显示，不覆盖旧历史、不重复计入重试批次、不沿用旧登录会话。
12. 同名非超管管理员、自动化通知方案及任务，默认使用本次导入的旧站资料覆盖新站对应残留；完全一致时复用，不再要求用户逐项选择保留哪一站。管理员按登录用户名，业务对象按对应管理员/父级及对象类型内的名称或实际业务唯一键匹配，不跨管理员仅凭同名合并。派单/交单领域改用第 16 条的整批恢复规则，不再按名称决定保留新站资料。
13. 被覆盖分组/方案内的员工名单及相关成员属性以旧站映射后的名单为准，包括旧站为空名单的情况；先移除新站残留成员关系，再恢复来源关系，不做名单并集。解绑不等于删除员工账号，迁移本身不清空全库；派单/交单之外未纳入替换的不同名目标资料不自动删除。
14. 覆盖前自动生成并校验独立加密备份，导入确认页汇总覆盖对象、成员移除及资金风险，再统一确认和二次验证管理员密码；确定的普通同名覆盖不逐项追问。新站超管身份、聊天角色合并历史、财务不相加、档案留证与正式部署逐项确认等既有保护继续有效。
15. 用户确认两站公告一致，公告及分类不导出、不导入、不覆盖，保留新站的发布/隐藏/置顶、轮播及素材；只被公告引用的文件不搬迁。不将此排除扩大到员工通知、广播投递或通知自动化，也不通过管理员覆盖或文件清理间接修改新站公告。
16. 用户确认新站完全未使用、没有历史订单，派单/交单按领域整批替换：来源分组、池、配置、员工关系、交单原文和有效/已用状态完整恢复；目标不同名残留也不继续参与业务。旧站的默认分组与各组默认池成为新站对应默认对象，保留来源默认标记、设置、池内数据和选择关系，不沿用目标初始化默认设置、不用目标值补缺失来源字段。事先核验未营业、独立备份并校验；发现真实订单/资金或活动派单关联即阻断并说明，不扩大删除范围。此规则待实现，不是现在清除新站或部署的授权。

正式实施的第一份交付是逐表覆盖清单，不以这张领域表代替完整盘点；清单确认前不宣称“除了订单什么都一样”。

|---|---|---|
| 管理员 | 二级及适用的非超管账号、密码校验资料、权限、启停、层级、备注与业务属性 | 旧超管映射新超管，不搬旧超管登录身份；新导入管理员在业务核对前不能登录操作 |

| 财务 | 钱包、流水、提款全状态、账本、基准、对账历史及必要的财务业务审计 | 重编号账本并换算游标；审核/操作者归属改写；禁止再次兑现奖励 |
| 历史订单 | 已完成精简订单，按现有统计口径保留状态、佣金与时间 | 不导真实金额、编号内容和产品；processing 只报告；订单金额/产品历史报表不承诺一致 |

| 通知与自动化 | 通知/收件已读状态、广播及投递关系、范本、方案、任务、成员、基线、进度、已执行标记和必要执行历史 | 不重放旧执行；与钱包奖励/通知关联一起校验，运行锁和队列重建；公告排除不影响本领域 |

| 实名与活动 | 实名/证件、登录历史、工时、评分等业务资料 | 未结束工时按最后心跳结束；不伪造在线状态 |

| 历史稽核/已删档案 | 纳入全站盘点和导出；账户、通知、聊天留证及私有附件按只读档案迁移 | 不把已删员工恢复在职；保留关联和审计属性，不重放删除/清理任务，目标既有档案不覆盖 |

### 4.1 明确不直接复制的内容

- 公告、公告分类及仅供公告使用的素材：用户确认两站已一致，保留新站现状；不包含员工通知、广播投递和自动化通知。
- 新站超管登录身份、旧站超管密码、两站现有会话、验证码/失败尝试/临时锁及临时令牌。
- 旧项目 URL、anon/service_role 密钥、SMTP/第三方凭据、部署配置；外部服务需在新站安全配置，不静默携带旧秘密。
- 正在进行的订单、派单会话/领取租约、数据库锁、实时信号和运行队列；恢复业务前按已迁移业务状态重新构建必要调度。
- 已明确排除的历史订单金额、订单号/交易号、产品及内容；辅助/审计字段也必须检查，不能通过订单池快照、财务请求原文等旁路把排除内容搬过去。
- 技术日志/缓存/幂等请求原文按依赖审查；防止重复发奖所需的业务执行标记必须保留，不能以“都是技术数据”为由全部丢弃。

标准全站流程不提供随意拆分关键类别的选择，也不要求人工全选；内部演练和覆盖前备份可以限定范围，但清单要明确标记为非完整站点备份。时间与统计沿用现行口径，界面 UTC+8 不改变既有 UTC 日界线。

### 4.2 员工详情、筛选和登录历史的明确验收

- 建立后台员工列表、详情弹窗、标签/备注展示、员工搜索和筛选的“页面字段 → 来源表/列/统计函数”清单。所有员工业务资料完整迁移，不把“已拷贝 users 若干列”当作员工资料已完整。
- 逐员工比较用户名/员工号、标签、备注、置顶、启停/验证状态、归属管理员、派单组/方案、注册及相关业务日期、资金、订单统计、提款/实名和关联详情；数值派生项按现有函数及已迁配置计算，不复制过期缓存。
- 在等价管理员权限下，按现有标签、备注/搜索、状态、分组等实际支持条件筛选，比较命中员工集合和总数，验证组合筛选、空值及分页；旧超管对应新超管后按业务身份比较，不要求内部 UUID 字面相同。
- 登录历史保留真实记录内容、时间、设备/IP及历史关联，去重后归同一导入员工；新站迁移后登录产生的新记录与旧历史连续展示并参与现有统计。新登录只增加真实新记录，不反复搬旧记录，不把历史 session_id 当有效会话。
- 同名员工替换前的新站原账号历史仍保留在备份/封存中，不自动混入导入账号；用户所说的续接包括导入的旧站历史与切站后新产生的记录。若需另合并目标替换前历史，须额外确认，不能隐式改变覆盖规则。
- 明确保留的例外仍有效：详细历史订单内容不迁移；处理中订单只报告；登录会话/运行态重建；新站超管身份保留；已确认的角色合并/目标属性保留差异记录在报告中，不以“一模一样”掩盖例外。

## 5. 管理员、配置、员工及聊天冲突

### 5.1 管理员和共享配置先于员工（来源优先；七表覆盖子阶段见第 20 节）

- 新站基本未使用，普通同名对象默认由旧站覆盖，不要求用户逐项比较取舍。先列出整体覆盖影响并保存校验备份，再统一确认；不能因为新站“基本空白”就略过实际资金、执行历史和关联检查。
- 旧超管映射操作的新超管，二级的 parent_id 以及员工/角色/方案 owner 全部改写；新站超管账号、密码、角色和会话不被覆盖。源非超管不能提升为 super_admin。
- 非超管管理员按现行登录规则下的用户名匹配；唯一同名目标以源密码校验资料、角色、父级、启停和业务属性为准，包含空值。更新并固化身份映射，不调用删除管理员，也不连带删除员工。覆盖后撤销该非超管的目标会话，新旧管理员均先停用，待依赖核对通过才恢复源启停状态。
- 同名管理员沿用目标身份时，所有来源 ID 和父子/归属引用必须改写，不能把源 UUID 直接覆盖到已有主键上。用户名撞新站超管或员工、源 ID 已被不同身份占用、同一匹配范围有多候选或源包自相矛盾仍阻断，不任意选一个覆盖。
- 范本、自动化方案等按各自实际业务唯一键及对应后的管理员/父级范围识别；有名称的对象在同一范围内唯一同名则覆盖，不能跨管理员仅凭同名合并。无名称的设置按对应归属和配置类型/键覆盖，未知键/列仍须审核。公告及分类已排除，不参与匹配和覆盖。
- 产品目录是全站共用的 `product_types`，没有管理员归属列且 `name` 全表唯一，因此按完整名称匹配，不按管理员分组匹配、不自动把相似名称或大小写差异视为同名。同名复用目标产品 ID，以来源启停、排序及业务时间等目录字段覆盖；旧站有而新站无则新增，新站独有的不同名产品保留。所有纳入迁移的产品引用改写为映射后 ID，不删除重建目标产品、不改动其既有订单历史；同 ID 被不同名称占用等身份冲突仍阻断。覆盖前须独立备份并校验。产品专用子阶段已实现并测试（第 21 节），返回来源到目标产品映射；全站业务引用的协调重写尚待接入，不代表七表子阶段或全站已支持完整产品关联迁移。
- 旧超管的业务设置覆盖对应的新超管业务设置，但不覆盖技术连接、密钥或安全身份；多个源超管合一导致源包本身出现不同值时，仍需明确唯一来源，不能按行顺序决定。
- 被覆盖分组/方案的员工关系按源映射后的完整集合替换，来源空集合也必须清空目标残留关系；成员设置、加入时间及必要进度一并迁移，不保留目标多余成员。员工原先在另一组时同步解除冲突关系，再按源归组并核对每员工唯一分组约束；只解绑，不删除目标独有员工。
- 派单/交单领域按第 5.4 节整批恢复，不逐条比较两站内容决定取舍；仍验证来源唯一键、引用和有效/已用状态。若目标实际存在使用或历史业务关联，与未营业前提不符，阻断整批替换并说明，不能抹掉关联或将已用资料重置可用。
- 配置按依赖导入，先固化 ID/键映射，再处理员工和内容引用。同名覆盖不等于清空全库：派单/交单整批替换范围之外，不同名且未纳入替换的目标对象、不可变档案和历史留证不自动删除；被覆盖对象内部的残留成员/规则则须替换完整，不能只覆盖标题。
- 所有覆盖均绑定服务器端计划、目标指纹、任务与备份回执；备份后目标发生变化须重新预检，不以客户端“已备份”声明解锁。媒体与内容覆盖仍遵循既有留证保护，不能为简化覆盖关闭保护触发器。

### 5.2 同名员工

- 用户名遵循现行登录规则，区分大小写；先核对输入去空格和存量用户名行为，不自动改名改号。
- 同用户名不同 ID：汇总余额、pending 提款、记录数量及覆盖名单 → 统一确认覆盖与管理员二次验证 → 独立加密备份并实际保存校验 → 现有封存留证 → 再干跑 → 导入。普通同名沿用导入优先，不再逐人选择保留哪站；实际资金风险必须醒目列出。
- 同 ID、同用户名也不能仅凭 UUID 相同就跳过本应覆盖的不同资料：只有确认是同包、同内容且已完成的对象才算已处理，绑定原任务的未完成账号才可续传。不同资料仍按导入优先的替换要求处理；若封存 UUID 冲突，先解决并验证全部关联的身份映射/恢复方案，不能改为静默保留目标或误报成功。
- 员工号或 ID 被不同用户名的账号占用、用户名与管理员冲突：阻断或跳过并报告，不能为追求一键而直接删除别人。
- 封存走 `archive_employee_without_media`；有媒体/通知证据则 `mutateAuditedContent('employee_delete', ...)`，不新增绕过留证的删除接口。
- 备份到封存之间再次核对目标未变化；备份任务先结束再开始导入任务，避免单活跃任务锁死流程。
- 旧新钱包和个人聊天不相加，目标原员工资料仍归封存身份。受控恢复必须解决同站检查、封存 UUID 与关联资料冲突，不能把备份可解密等同可直接恢复。

### 5.3 聊天角色

1. 在映射后同一管理员、相同 aaa_service/ccc_service 内匹配；编号和名称相同自动合并，名称唯一相同可预选并标依据。
2. 同名多候选、仅编号相同但名称不同，必须选择；无候选新建，显示编号占用则安全生成新号并报告。多个旧角色合一需确认。
3. 合并保留目标角色属性；指定员工可见范围的改变另确认、审计，只加入成功导入的对应员工。新建角色复制设置，受限名单过滤为空不得误变全员开放。
4. 消息按 ID、归属及内容去重；工单按槽位及编号处理冲突；备注保留目标、源备注取舍报告化，不能直接按源原始行数验收合并结果。
5. 范本/自动消息配置迁移后对应实际引用；富卡冻结真实 HTML，媒体重写后重新算目标哈希，保留源目标快照映射。同哈希还核对内容，不把 MD5 当安全认证。
6. 完整空站导入应能准确重建已发标记，避免登录补发。目标既有不同自动消息配置导致无法对应时明确报告，不静默重发或宣称完全相同。

### 5.4 派单/交单整批恢复与默认池（规则已确认，待实现）

- 对已核验未营业的新站，先独立备份并保存校验，再在维护窗口按明确领域清单替换派单分组、订单池、池内数据、设置、成员及交单原文/有效/已用状态；不让用户逐条比较两站内容，不保留该领域目标独有的可用残留，也不扩大到产品、管理员账号、公告或自动化全表清空。
- 默认身份以来源为准：旧站 `dispatch_groups.is_default` 和每组 `dispatch_order_pools.is_base` 连同来源选择模式、配置、内容与引用完整恢复。不得仅因新站已有一个 Base 池就跳过来源默认池，不得将来源默认池降为普通池并继续使用目标初始化池。
- 建组触发器若自动生成默认池，它只能作为导入中的临时占位，不能视为已导入；必须以来源默认池的完整业务数据取代并固化来源到目标的引用映射，禁止残留目标默认值或为来源缺失字段兜底。来源必需默认池缺失或多重默认等矛盾须报错，不能改用新站默认池。内部 ID 映射不能成为保留目标设置的理由。
- 受保护默认池、外键、真实历史或运行态关联仍需受控处理，不用 `TRUNCATE ... CASCADE` 或关闭保护来强行清库；目标未营业的预检、备份后变化检查、维护隔离与恢复验证必须先实现。发现实际业务则阻断并说明，不能以用户预期空站为由连带删除业务。正式执行的范围、数据替换和任务调整仍需另行确认。
- 验收须故意让两站默认分组、默认池 ID、设置、内容及默认/随机选择模式不同：导入后只能选中来源对应默认池，池内数据和员工归组与来源一致，目标残留不参与；自动生成的空默认池不得抢占默认身份。重复导入不多建默认池，失败不放行半成品。这些是待实现的功能测试要求，不代表已通过。

## 6. 自动化和资金的一致性

### 6.1 自动化随站迁移，不重新加入方案

需要一起盘点和迁移方案、任务定义/版本、启停与激活时间、成员及加入时间、基线、周期/阶段进度、唯一执行标记、通知、奖励流水和必要执行历史。原方案“导完再把所有员工加入新方案”不适用于全站迁移，会改变进度口径。

同名自动化方案/任务按对应管理员及方案层级匹配，唯一匹配则用来源定义、任务集合、成员和进度替换目标残留，不只改标题，不合并成员、不重建基线。源方案内已不存在的目标残留任务不能继续执行；按留证规则安全停用/封存并移出当前方案。已有源执行标记随任务版本及员工映射恢复，不能把目标旧进度简单相加或让目标旧标记误抑制来源未来通知。若目标已有真实发奖/通知，先核对并保存其财务及执行证据；无法安全隔离历史时阻断该对象，不能将“覆盖”当作重新兑现奖励的理由。

先暂停新站相关评估/执行，按依赖写入状态，核对执行唯一键、已发通知及已兑现奖励，再恢复预期任务状态。不直接迁移旧队列锁和领取令牌；停站窗口内未完成的评估/通知需有截止点和明确重建规则，避免漏发和重复发奖。首次登录、累计/每日订单、工作日、年度日期和循环阶段都要续接测试。

既有草案把通知 automation_execution_id 清空等行为要按新范围重新审核，不能照搬。财务幂等记录若关联执行去重必须保留等价保护；不能单纯全部排除，也不能导入含被排除订单细节或秘密的请求原文。

### 6.2 资金核心

员工账号（停用）、钱包、基准、账本、流水、提款等先暂存，再按员工一个事务验证提交。失败回滚该员工核心。其他大表分批，不能承诺跨请求自动全量回滚；取消不自动删除已提交资料。

以实际 `reconcile_wallet_from_ledger` 定义核对：冻结 = pending 提款合计；可用+冻结 = 基准金额+基准游标后账本增量；总收入 = 基准收入+其后收入增量。金额用 numeric/稳定十进制，浏览器浮点不是最终判据。缺基准老账号必须验证首次建基准不改钱，异常源资料阻断，不自动修平。

账本按旧编号顺序用目标序列重编号，基准游标对应旧编号 ≤ 旧游标的最后一条新编号，没有则 0。测试目标已有账本、序列间隙、游标超界、并发对账与唯一键。

### 6.3 触发器和维护

只旁路已审核副作用触发器，保留外键、封存/媒体/组隔离/富卡保护；审核名称、定义、启用状态，并精确恢复原状态。异常、超时、锁冲突不得残留关闭状态；不改用全局复制模式绕过保护。

范围扩大后，admins、配置、产品、自动化、档案等纳入迁移表的触发器、权限和审计需重新纳入，不复用员工表白名单即宣称安全。关闭触发器会取表锁，须测试真实 PostgreSQL 行为、PostgREST 缓存、权限、超时及查询索引。

正式切站停止旧站相关写入、新站维护中阻止业务写入并管控自动任务，账号停用或页面提示不能替代服务端措施。cron/权限等正式调整逐次确认；导入后按依赖恢复任务，旧站保持停写，pending 提款只在新站审核。

## 7. 加密分卷与媒体

- `.edx` 版本化容器，内层 ZIP 流：全站清单、分表 NDJSON、媒体和身份/配置映射；区分全站配置卷、员工卷和媒体依赖，必需卷不全不能宣布全站成功。
- AES-256-GCM 分块（初始约 1 MiB）；PBKDF2-SHA256 600,000 次、每卷随机盐、唯一 nonce；认证包/卷/块编号和结束信息，拒绝篡改、截断、重排、重复块、跨包换卷。
- 每文件/卷 SHA-256；包随机 ID；约 150 MB 是分卷目标，大员工/素材可跨卷，流式有界处理，不同时加载所有明文。
- 口令至少 14 位，推荐生成 24 位随机口令、确认输入、与文件分存；口令不进日志、数据库或持久浏览器存储。管理员二次验证密码不同于加密口令。
- 普通索引/报告不暴露密码、证件、聊天或逐账户资金；敏感报告在加密范围或登录后查看。Chrome/Edge 优先流式写盘，不支持时明确内存限制。覆盖前备份需可验证保存/重新读取校验，下载触发不是保存成功。
- 独立 Node 20 解密脚本与网页格式一致，仅应急使用；正常新站直接选文件和输口令。
- 收集聊天、富卡、通知、品牌图标、证件、档案等纳入迁移领域实际引用文件，排除仅供公告使用的素材，支持范围内的结构化及 HTML 引用。虚拟头像不下载；相对/签名/data URL 明确处理，外链/缺失报告，不抓任意外网。
- 同路径同 SHA-256 才复用；冲突改名并映射所有引用，不覆盖目标不同内容。重写后更新富卡哈希和相关内容对应特征，不能只替换域名。
- 自建管理员会话不等于 Storage 身份。逐桶核对公开/私有、路径前缀、大小/MIME、CORS；必要时单独设计绑定任务/对象/大小/时效的签名或代理，不放宽整个桶，不放 service_role 到浏览器。
- 限制文件/解压条目数、总量、单行、路径与请求大小，拒绝穿越、恶意 HTML 和未允许资源。在线权限问题另列整改，加密备份不是在线权限修复。

## 9. 标准用户操作流程

### 9.1 旧站默认全部导出

1. 超管进入「資料遷移」→「導出」，默认「全站導出」，不用选员工/管理员/类别。
2. 自动盘点全站，展示管理员/员工/配置/内容/媒体数量、pending 提款、processing 订单、在线/工时、源站异常及预计大小。
3. 正式切站安排停写及源站/数据库备份；演练明确标记，不把可变数据视为严格快照。
4. 设置并确认加密口令，验证管理员密码，固化全站范围、格式、源站和截止信息。
5. 按依赖/游标分页，初始每页不超过 5,000 行且受字节限制；媒体有限并发（初始 4），按真实回执显示进度。
6. 导出前后比较指纹及必要摘要，变化重读（最多 3 次），持续变化不标成功；正式一致性以停写窗口或可证明快照为前提。
7. 保存并校验全部卷、索引及报告，提示口令分存和 pending 提款交接；不自动删除旧站。

### 9.2 新站导入

1. 新站先有可用超管、兼容代码/数据库/必要服务及 Storage；不要求先手工建立二级管理员或业务配置。
2. 选全套文件、输原口令，验证加密、清单、必需卷和安全限制；不写业务资料。
3. 预检目标结构/触发器、源站身份、账号/配置冲突、媒体权限及维护条件。
4. 自动把旧超管对应新超管，展示将新建/覆盖的管理员、配置和员工，列出被替换的分组/方案成员及派单/交单整批替换范围；默认池明确显示旧站对象成为新站默认池，其他普通唯一同名对象默认来源覆盖，不逐项选取。只有歧义、身份交叉冲突、源内矛盾及真实业务风险需单独解决。
5. 统一确认覆盖清单、确认语及管理员密码，先独立备份并实际保存校验；备份与目标指纹绑定后才允许替换。员工继续走现有封存留证；管理员受控更新，不套用员工封存或连带删除流程。
6. 建立/续接绑定全站包的任务；先创建/覆盖停用的非超管及配置 ID 映射，处理超管归属，覆盖的非超管撤销原会话。
7. 上传依赖媒体，导入分组/产品/模板/角色/规则（不导入公告），按员工提交资金及精简订单等历史/聊天；再写自动化成员、进度、执行标记和必要档案关联。具体拓扑由逐表盘点确定，循环依赖分阶段验证，不临时关外键。
8. 核对配置、管理员权限/归属、所有员工财务/统计、通知与自动化、档案和文件。单员工失败可单独停用续传，共享基础失败则相关阶段及整体成功阻断。
9. 只有依赖完整、自动化状态/奖励去重验证后，按原状态恢复账号/方案/任务；全站维护门槛满足后才对外放行。
10. 人工验收超管/二级/员工登录及权限、分组和提款条件、每日明细、聊天、通知和自动化续接，另核对新站公告未被改动，核对报告后恢复新站业务；旧站保持停写。

## 12. 测试与验收

### 12.1 全站覆盖与管理员

逐表/配置键覆盖测试，未知新增表/列/触发器需审核；空白新站一套文件即可建立二级、分组、产品/模板/规则和所有在职/停用员工，不依赖用户手动重建。公告是用户明确排除项，不从来源创建；验证其正文、分类、归属、发布/隐藏/置顶、轮播和现有素材在迁移前后不变，导出清单与必需卷不得要求公告。

验证新超管密码/角色/会话身份不被源文件覆盖；旧超管业务完整接管；同名非超管的两份密码校验资料、角色、层级、启停/空值及业务设置按源覆盖，原目标会话撤销且核对前不能登录，不经删除管理员也不删除其原名下员工。二级只见映射后归属范围，跨组不能访问；用户名撞超管/员工、ID 被不同身份占用、多候选、层级环和源内冲突仍有保护。

配置/内容按来源优先比较，空站与同名残留场景均应与源对应业务一致；目标保留项差异报告，不宣称无差异。派单/交单验证领域整批替换（含不同名残留）、来源默认分组/池身份及全部设置/内容恢复，不能使用目标初始化默认值；自动化方案按同名来源覆盖但不全表清空。分别验证配置整体替换、旧成员移除、源成员归组、空名单清空、另一组的成员关系同步解除、每员工唯一分组、管理员映射不串组，其他领域不同名目标不全库删除；覆盖前备份保存/重读校验与目标变化阻断必须验证。已删员工只作为档案、稽核证据关联和私有附件验证，不恢复账号。

产品目录验证全站唯一名称匹配、同名不同 ID 复用目标并重写引用、来源启停/排序覆盖、无同名新增、目标不同名保留及已有订单历史不改；同 ID 异名称与源内矛盾仍阻断，重复导入不重复建产品，覆盖前备份和目标变化门禁有效。目录本身已通过产品专项验证（第 21 节），全站关联协调和真实浏览器验收仍待完成，不以库存意图测试代替功能验收。

交单资料验证整批按来源恢复、唯一键映射、原文及有效/已用状态保留、目标独有残留不继续可用、重复导入不增加可用数量；目标真实使用关联须阻断未营业模式，不得因替换重新可用。源内矛盾或映射不唯一不能按记录顺序任选，不为两站名称或内容不同逐条比较取舍。

### 12.2 财务、订单和内容

资金/原密码/完整业务属性双库往返，标签、备注、置顶、空值、状态、归属和业务时间逐项比较；用第 4.2 节页面字段清单及组合筛选结果验收。账本比较顺序和内容允许重编号；精简订单只比保留字段。逐员工对比日统计、总计、完成数、详情、交易和提款条件；对应配置一并迁入后应一致，金额/产品历史报表明确不验成相同。

导入后实际新增一次登录，验证旧历史仍在、新记录归同一员工、时间排序/设备详情/登录统计正确；相同历史批次重放不重复。同名替换验证本次导入标签/备注等确实覆盖目标（含导入值为空），目标原记录仅在备份/封存；同 UUID 但资料不同时不能错误跳过。

验证冻结/pending、游标边界、缺基准、源异常、精度、唯一键、真实及 cron 对账零非预期修正；不多出佣金/奖励/账本/通知。覆盖当天订单/跨 UTC 日、processing 不导入、占位产品停用和占位金额不误展示。

同名员工备份→留证→导入及受控恢复；聊天全部匹配分支、角色设置保留规则、受限可见性、消息异内容冲突、工单/备注合并；范本/富卡/自动消息配置和已发记录、未有聊天的角色也完整。

### 12.3 自动化续接

同一员工迁移前后比较方案、任务版本、基线、阶段、周期及唯一执行集合。首次登录、跨日、工作天数、循环与年度日期、已发通知、奖励流水、停站未完成评估均测试。恢复 worker/员工登录后历史奖励不再发、未来应发不漏发；不能用“全部任务先关掉”通过零重复测试。

同名方案但触发条件/奖励不同，验证来源完整覆盖目标定义和任务集合、成员按源替换而非并集、加入时间/基线/进度不重置、目标残留任务不执行；重复导入不重复发通知/奖金。目标已有真实奖励时核对保留证据及去重隔离，不得直接抹掉执行标记；只覆盖标题或保留旧任务配置都不能算通过。

### 12.4 文件、任务和安全

错口令/翻转字节/截断重排/缺卷跨包/损坏清单/解压规模/路径/不安全 HTML；媒体同路径同内容、同大小异内容、私有读取与签名过期、缺失/超限/外链、中断和有界内存。

超时前后提交和未提交、暂停取消关闭、会话/任务过期再认证、多标签、跨包接管拒绝、回执不重复、finish 全站门槛。非超管、无效令牌、跨任务对象/未知列和越权配置/角色写入拒绝。

真实 PostgreSQL 锁、触发器失败及原状态恢复、云端 Storage 行为须隔离测试，不靠 PGlite 替代。已有回放失败逐一解释，关键新增失败立即阻断。

### 12.5 浏览器和回归

实际操作全站导出/导入、超管保留、管理员/配置冲突、同名替换、角色合并、真实进度、异常和续传。推荐桌面 Chrome/Edge 大规模迁移，兼测窄屏和可用 WebKit；环境无法测试时明确说明，不索要明文正式密码。

## 13. 正式部署与失败处理

1. 用户下令后先实现和验证 A–F，不把开始实施当正式修改数据授权。
2. 上线前只读核对实际库迁移/结构/触发器定义状态/权限/配置/Storage/cron/超时；本次未做正式检查。
3. 列出 SQL、服务端和前端依赖、锁风险、备份恢复方案，分别批准数据库、媒体服务/权限和任务调整。数据库先于依赖它的前端；前端按现有流程由用户发布，推送不等于部署。
4. 用隔离目标演练全站包，必要的少量对象演练仅作为辅助，不以员工小包冒充全站验收；演练不能污染正式导入去重或奖励状态。
5. 新站需要兼容代码/数据库、可用超管、存储及外部服务连接；不需手动重建业务管理员/配置。建库历史缺口先解决，不盲跑全部旧 SQL 忽略失败。
6. 单独确认切站时间、源站停写、目标维护、pending 提款责任、任务暂停/恢复与备份保留，再允许正式全站迁移和任何封存覆盖。
7. 全站核对后按依赖恢复账号、规则和任务，人工验收再开放新站；旧站保持停写，避免双站做单、登录和重复打款。
8. 保留加密文件、分离口令、清单报告、配置覆盖前备份、切站记录及源站；保留期由用户确认，不自动清源库或媒体。

资金核心失败回滚该员工事务；其他分批失败留检查点且相关账号/任务不开放。共享配置失败会阻断依赖及全站成功，不能仅跳过后称全部完成。取消不自动撤销已修改配置/角色，数据库 DROP 也不是业务回滚。已开放新站并产生新交易后不能直接切回旧站，先核对切站后变化。管理员冲突或恢复不可验证时先停，不用删除关联员工等破坏性动作绕过。

## 14. 实施前仍需明确的边界

- 当天精简订单展示：用户已确认“标注历史导入”，允许最小修改员工订单展示，保留原日期/佣金/统计，不把占位金额/产品/编号显示成真实交易资料；本轮尚未修改该页面。
- 覆盖前备份恢复：推荐受控且演练通过的同站恢复路径，解决封存 UUID/关联冲突；不是放开所有保护或一键撤销整个迁移。缺少恢复能力时不得承诺一键导回。
- 详细历史订单与业务配置边界：用户已确认“只省历史详情”，继续营业需要的派单/交单原文及防重复状态一起迁移（可以含金额/交易号），但不能借此复制已处理历史订单的其他原文快照。已在覆盖库存中区分，逐字段实现仍待完成。

最终放行标准：全站覆盖清单无未说明缺项，新超管身份保留，管理员权限归属/配置/员工资金统计/内容文件/档案核对通过，自动化正确续接而非重置，无未解释冲突或重复奖励，真实进度与全站结果一致。例外和恢复限制必须明确，不能用“全部一样”掩盖已确认排除项或目标保留差异。

## 17. 继续实施：文件容器与触发器安全（本地，未部署）

### 17.1 已实现的独立模块

- `container.ts`、`manifest.ts`：单卷 ZIP32 STORED 双遍流式读写，首遍得到 CRC/大小/SHA-256，次遍输出标准头并再核对内容，拒绝两遍间变更；与独立 `fflate.Unzip` 逐字节互操作测试通过。文件源须可重开，后续 exporter 应先把数据库分页/媒体落到可重复读取的临时文件，不缓存整份明文，也不重复查询变化中的资料来代替同一份文件。
- 清单最后写入，严格版本/身份/文件路径/大小/哈希；解析完整校验中央目录、EOCD 和真正 EOF，外层结束认证完成才返回验证结果。损坏、错口令、缺卷、重复卷、混包、路径穿越、重复路径、压缩文件和超限拒绝。
- 默认每次输入最多 1MiB、每卷最多 4096 项、清单 2MiB、单文件 512MiB、业务数据 1GiB、ZIP 1100MiB、单行 1MiB；这些是格式安全上限，不是自动 150MiB 分卷实现。v1 不接受 ZIP64/压缩/数据描述符/目录/符号链接/额外字段。归档内部路径暂为便携 ASCII；原始中文/特殊文件名须在未来媒体映射中单独保留，不能据此漏导文件。
- `sha256.ts`：常量内存增量 SHA-256，与 Node 独立实现、标准向量、百万 a、填充边界、偏移视图及复用 Buffer 比对。
- 临时 sink 逐块背压，可取消等待中的输入/写入；`append` 必须只写隔离临时区，`abort` 必须原子阻断待完成/未来写入并清理（包括迟到完成）。解析器的 Promise 取消不等于第三方存储回滚；真实浏览器临时存储适配器及其取消清理仍未接入。NDJSON 此层只校验 UTF-8/行长，业务列/身份/资金验证仍由后续导入器承担。
- 解密新增可选 `expectedMetadata`/`AbortSignal`，绑定外层与清单的包/卷 ID；未改变现有文件外层格式或应急 Node 解密工具的兼容性。
